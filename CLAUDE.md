# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

YieldVault-RWA is a decentralized vault protocol on the **Stellar network**. Users deposit USDC and earn yield generated by tokenized real-world assets (e.g. Korean sovereign debt) via Soroban smart contracts. It is a monorepo: Rust/Soroban contracts, a Node/Express backend, and a React/Vite frontend.

- `contracts/vault/` — main Soroban vault contract (deposit/withdraw, yield accrual, strategy management, DAO governance, RWA shipment tracking)
- `contracts/mock-strategy/` — test-only mock strategy and mock price oracle
- `contracts/share-price-math/` — shared share/asset math library used by `vault`
- `backend/` — Express + TypeScript API with Prisma (SQLite locally, Postgres in prod)
- `frontend/` — React + Vite + TypeScript app, Freighter wallet integration
- `packages/api-schemas/` — shared Zod schemas consumed by both `frontend` and `backend`
- `docs/` — architecture, runbooks, testing strategy, ADRs, threat model, etc. (see key docs below)

## Common Commands

### Contracts (Rust/Soroban, run from repo root)

```bash
rustup target add wasm32-unknown-unknown   # one-time
cargo test -p vault                        # all vault unit/integration/invariant tests
cargo test -p vault <test_name>            # single test by name (substring match)
cargo build -p vault --target wasm32-unknown-unknown --release
cargo fuzz run share_price_math            # fuzz target (contracts/vault/fuzz/)
```

Rust toolchain is pinned via `rust-toolchain.toml` (1.85.0, with `rustfmt`/`clippy`).

### Backend (`cd backend`)

```bash
cp .env.example .env && npm install
npx prisma migrate dev   # local SQLite DB at backend/prisma/dev.db
npm run dev               # tsx watch, http://localhost:3000 (health: /health, readiness: /ready)
npm test                  # jest, all tests
npx jest src/__tests__/<file>.test.ts        # single file
npx jest -t "<test name>"                    # single test by name
npm run lint               # eslint src
npm run build && npm start # compile + run compiled server
npm run ci:governance       # lint + test + migration/ADR/snapshot checks (mirrors CI gate)
```

Leave `DATABASE_URL` unset for the default SQLite path; leave `REDIS_URL` unset to use in-memory fallbacks for rate limiting/nonce storage.

### Frontend (`cd frontend`)

```bash
cp .env.example .env && npm install
npm run dev                 # vite dev server, http://localhost:5173
npm run test:run            # vitest, all tests, run mode
npx vitest run src/path/to/File.test.tsx     # single file
npx vitest run -t "<test name>"              # single test by name
npm run lint                 # eslint .
npm run build                # tsc -b && vite build
npm run test:e2e             # playwright (builds first)
npm run test:cypress         # cypress smoke suite
```

Set `VITE_VAULT_CONTRACT_ID` to the same contract ID the backend targets for end-to-end transaction flows.

### Root-level

```bash
npm run test   # vitest run — repo governance/validation scripts in scripts/*.ts (env matrix, contribution standards, NFR baselines, etc.), not app code
```

## Architecture

### Contracts (`contracts/vault/src/`)

The vault contract is split by concern across many files rather than one monolith — read the relevant module rather than grepping `lib.rs` for everything:

- `lib.rs` — public contract entry points and top-level wiring
- `admin.rs`, `permissions.rs` — two-step admin transfer, access control
- `strategy.rs`, `strategy_registration.rs`, `strategy_heartbeat.rs`, `benji_strategy.rs` — pluggable `StrategyTrait` connectors and whitelisting
- `timelock.rs` — generic timelocked-change primitive used by fee, treasury, and oracle address changes (Issue #969 pattern: `queue_*` → wait → `execute_*`/`cancel_*`)
- `fee_math.rs`, `math.rs`, `packed_storage.rs` — share/asset accounting and storage-efficient encoding
- `oracle.rs` — standalone price validation (heartbeat, deviation, decimals); wired but optional (`is_oracle_enabled`)
- `emergency.rs`, `emergency_rescue.rs` — pause/unpause and emergency asset recovery
- `withdrawal_queue_safety.rs` — large-withdrawal timelock (separate from the generic admin-change timelock)
- `whitelist.rs`, `storage_registry.rs`, `upgrade.rs`, `external_calls.rs`, `errors.rs` — supporting infra
- `*_tests.rs`, `test.rs`, `invariant_tests.rs`, `formal_verification_tests.rs`, `fuzz_math.rs`, `deposit_withdraw_props.rs` — test suites are colocated with the module they exercise; property/invariant tests live alongside example-based ones

`share-price-math` is a separate crate (not `cdylib`) so its math can be unit-tested and reused without pulling in `soroban-sdk`'s contract machinery. `mock-strategy` provides `MockKoreanSovereignStrategy` and `MockPriceOracle` for contract tests only — never deployed.

Full contract API reference and storage key layout: `docs/CONTRACTS_ARCHITECTURE.md`.

### Backend (`backend/src/`)

Flat `src/` (no subdirectory nesting beyond `middleware/`, `services/`, `types/`) — most modules are one concern per file, named descriptively (e.g. `webhookDeduplication.ts`, `withdrawalRecovery.ts`, `retryBudget.ts`). Notable groupings:

- Request entry: `index.ts`, `vaultEndpoints.ts`, `transactionEndpoints.ts`, `walletAliasEndpoints.ts`, `referralEndpoints.ts`
- `middleware/` — cross-cutting HTTP concerns (auth, rbac, rate limiting, geofencing, tenant guard, versioning, CORS, correlation IDs)
- Soroban integration: `sorobanClient.ts`, `sorobanBatchClient.ts` — the backend reads/submits against the same Soroban RPC the frontend and contracts use
- Reliability primitives: `circuitBreaker.ts`, `retryBudget.ts`, `idempotency.ts`, `optimisticConcurrency.ts`, `eventOutbox.ts` (outbox pattern for reliable event publishing), `gracefulShutdown.ts`
- Background jobs: `eventPollingService.ts` (polls Soroban events), `apySnapshot.ts`, `positionReconciliationJob.ts`, `dbBackupJob.ts`, `withdrawalRecovery.ts`
- Audit/compliance: `auditLog.ts`, `vaultAuditLog.ts`, `adminAudit.ts`, `writeAheadAuditLog.ts`, `auditRedaction.ts`, `criticalEntityLifecycle.ts`
- Data layer: `prismaClient.ts`/`prisma.ts` (Prisma ORM over Postgres/SQLite), `redisCache.ts` (optional, falls back to in-memory)

Persistence uses Prisma (`backend/prisma/schema.prisma`); migrations are checked via `scripts/check-migrations.js` and `check:migrations:canary` as part of `ci:governance`.

### Frontend (`frontend/src/`)

- `pages/` — top-level routed views (Portfolio, Analytics, TransactionHistory, Admin, VaultComparison, Settings, TransactionReceipt)
- `components/` — shared and feature UI (`components/shared/`, `components/ui/`, `components/EarningsCalculator/`)
- `lib/api/` — typed API client layer: `client.ts` (fetch wrapper), `schemas.ts`/`validation.ts` (Zod, shared with `@yieldvault/api-schemas`), `telemetry.ts`/`useApiTelemetry.ts`, `correlationInterceptors.ts` (propagates the backend's correlation IDs)
- `forms/` — form flows split into `forms/components/` and `forms/schemas/` (Zod schemas per form)
- `hooks/`, `context/`, `config/`, `data/`, `i18n/` — standard app-level concerns
- Stellar wallet connectivity goes through `@stellar/freighter-api`; on-chain reads/writes go through `@stellar/stellar-sdk` against the same Soroban RPC endpoint configured for the backend

Note: `pages/Settings.tsx.bak`, `Settings.tsx.backup2`, and `Settings_original.tsx`/`Settings_new.tsx` are stale artifacts alongside the live `Settings.tsx` — don't assume all `Settings*` files are active.

### Cross-cutting

- `packages/api-schemas` is the single source of truth for request/response shapes shared between `frontend` and `backend` — update it first when changing an API contract, then update both consumers.
- Events: the vault contract emits signed events (`deposit`, `pndwdraw`, `withdraw`, `feechg`, `mindepchg`); the backend's `eventPollingService.ts`/`eventOutbox.ts` consume and re-publish them. See `docs/WEBHOOK_INTEGRATION.md` and `docs/WEBHOOK_EVENT_SCHEMA_CATALOG.md`.
- Timelocked admin changes (fee bps, treasury address, oracle address) follow a consistent `queue_*` → `execute_*`/`cancel_*` pattern in the contract, configurable via `sensitive_timelock_delay` (0 disables, otherwise ≥ 1 hour).

## Conventions

- Branch naming: `feat/<issue>-<desc>`, `fix/<issue>-<desc>` (see `CONTRIBUTING.md` for the full list).
- Secret scanning runs via a Husky pre-commit hook (`scripts/secrets-check.js`, gitleaks-based) plus GitHub push protection — do not bypass with `--no-verify` for real secrets.
- Commit messages and PR descriptions must not include AI/model attribution — this is enforced by repository convention, not tooling.
